# Firebase setup runbook (FEAT-010 / DEC-007)

The active `iosApp.xcodeproj` is generated by XcodeGen (`mobile/iosApp/project.yml`) and
resolves every iOS dependency through SwiftPM (`Firebase 12.10.0`, `RevenueCat 5.87.1`,
`GRDB 7.6.0`, `Kingfisher 8.12.0`). The production integration is a native Swift Firebase
bridge in `AppDelegate.swift`. `iosApp.xcworkspace` is kept as a thin wrapper that
references only `iosApp.xcodeproj`, so `-workspace` commands keep working; the CocoaPods
lane (`Podfile`, `Podfile.lock`, `Pods/`) is gone — do not re-add it or run `pod install`,
which re-injects Pods build phases into the generated project and breaks the build.
Do not upgrade unrelated dependencies.

## Firestore Configuration (`config/app`)

Dynamic app configuration is fetched from Firestore document collection `config`,
document `app` (`config/app`), with public read access (no Firebase Auth sign-in required).

### Document Schema for `config/app`:

| Field Name | Type | Default Value | Description |
| --- | --- | --- | --- |
| `api_baseurl` | String | `https://pose-extract-server-production.up.railway.app` | Base URL for the AI Pose backend API. Must be valid HTTP/HTTPS URL without trailing spaces. |
| `account_enabled` | Boolean or String | `false` | Account switch for the Account surface (sign-in, Saved, account deletion). Accepted true values: `true`, `1`, `yes` (case-insensitive). Fails **closed**: a missing key, a non-boolean value and a fetch error all resolve to `false`. |
| `extractPoseEnabled` | Boolean or String | `false` | Enables/disables pose extraction UI entry points (Add Pose button, job submission, form submit). Fails **closed**: a missing key, an invalid value, a fetch error, an offline launch and a fresh install all resolve to `false`. Only an explicit `true` (or its accepted string form) turns it on. |

> `account_enabled` sits on the same document as `extractPoseEnabled` and `paywall_enabled`; there
> is no second account key.
>
> `extractPoseEnabled` was default-on until this build (payload `schemaVersion` 1). A cache written
> by an older build is read with extraction **off** (`AppConfigService.resolveInitialPayload`), even
> if it stored `true`, because that `true` was the old default rather than an operator's opt-in.

*Note: Firestore security rules for `config/app` should allow public read access without requiring authentication.*

## Xcode environment selection

Run the `Dev` or `Prod` scheme generated from `project.yml`. The selected
scheme resolves `AIPoseEnvironment` and `AIPoseBuildConfiguration` through the
matching `Config/*-*.xcconfig` file. Firebase remains best-effort and is not
used as the environment descriptor.

## Startup behavior

- On launch, `AppDelegate.swift` reads the plist from the app bundle and
  validates its shape (required keys present, `API_KEY` looks like a real key).
  Missing, malformed, or placeholder-shaped configs are skipped: the app boots
  without Firebase.
- First paint is **never blocked by network or Firestore**: the root view is built
  immediately from the last successfully fetched payload cached in UserDefaults. Before
  the first successful fetch, compile-time defaults are used.
- When configured, a background task fetches `config/app` from Firestore within a
  bounded 5-second endpoint update window. Successful payloads are cached. Fetch error
  or offline failure keeps the current cached/default values; missing fields in a successful
  document use their field defaults. The root view is rebuilt only if an applied value changes.
- `extractPoseEnabled` is a Boolean (or accepted Boolean string) field on the public-readable
  `config/app` document. Set it to `true` to show pose extraction and Jobs entry points; any other
  value, a missing field, or an unreachable document leaves them hidden. The other fields are
  `api_baseurl` (String) and `account_enabled` (Boolean or parseable Boolean string; defaults to
  `false`).
- Debug Simulator runs can override flags with launch arguments:
  - `-AIPoseAccountEnabled true|false`
  - `-AIPoseAccountsEnabled true|false` (same switch as `account_enabled`; the older
    `-AIPoseAccountEnabled` wins when both are passed)
  - `-AIPoseExtractPoseEnabled true|false`
  - `-AIPosePaywallEnabled true|false` (same switch as `paywall_enabled`)
  - `-AIPosePurchasesConfigured true|false` (QA precondition only: treat the purchase
    context as **configured, and the signed-in user as holding no entitlement**, so
    the paywall is reachable on a build whose RevenueCat key /
    `REVENUECAT_ENTITLEMENT_ID` is still a placeholder. It fabricates no plan,
    purchase or access — a purchase there fails cleanly as `unavailable`.)
  - `-AIPoseAPIBaseURL <url>`
  (Compiled out of Release builds: no launch-argument lookup for these flags exists in a Release
  binary. The two new switches only override the value resolved from Firestore; with no argument the
  fail-closed defaults stand.)

## dSYM handling (Crashlytics)

- Crashlytics dSYM upload is a release build concern. Run the standard
  Crashlytics upload-symbols step from CI or a local release archive.
- Upload failure must be treated as a diagnostic failure, never an app-launch
  failure. No dSYM upload runs during local verification.
